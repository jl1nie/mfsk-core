これは何か

FT8・FT4・FST4・WSPR・JT9・JT65・Q65・MSK144 — WSJT 系デジタルモードの復調と変調を、ひとつの純 Rust ライブラリにまとめたものです。 DSP、同期相関、LLR、誤り訂正（LDPC / 畳み込み / Reed-Solomon / QRA）、メッセージ符号を共通の土台として共有し、その上に各モードが載っています。

WSJT-X はこれからも基準実装です。各ファイルは移植元の lib/*.f90 / lib/*.c を明記しています。 このライブラリの存在理由は WSJT-X を置き換えることではなく、 Fortran + C + Qt のデスクトップアプリが行けない場所へ、同じアルゴリズムを持っていくことです。

マルチプラットフォーム — ソースは1つ

行き先ターゲット 状態と備考
デスクトップ / サーバx86_64, aarch64既定構成。rustfft + rayon。cargo add mfsk-core ですぐ使えます
ブラウザwasm32-unknown-unknownrustfft の WASM SIMD。+simd128 の明示を忘れずに（既定では付きません）
Android / iOSNDK arm64-v8a ほかNEON。C ABI 経由で、Fortran ランタイム不要
マイコンno_std + alloc — ESP32-S3 / RP2350 / Cortex-M実運用中。fft-extern + fixed-point、FFT は呼び出し側が注入
C / C++ からstaticlibmfsk-ffi（全モード）／mfsk-ffi-ft8（FT8 のみ）。ヘッダは cbindgen 生成

差し替えられるのは行き先だけではありません。DSP と FEC 全体がスカラ型トレイトで抽象化され、ホストは f32、 マイコンは u16 スペクトログラム + i16 DFT + Q11i16 LLR + 整数 BP — コードは同じ一本です。FFT も外部注入。モードはすべて feature フラグです。

呼び出し側が用意するもの

  • FFT の実装ひとつ — fft-extern でファクトリ関数を1つ提供するだけ
  • アロケータ — no_std + alloc。スロット単位の作業領域は PSRAM で構いません

求めるのはこの2つだけで、スクラッチバッファの配置に悩む必要はありません。 スロットあたりの作業領域：スペクトログラム 約360 KB（PSRAM 可）、候補セット 約120 KB、LDPC BP スクラッチ 約12 KB。

速度 — 同じ整数パイプラインで

Ryzen 9 9900X（固定小数点）約 6 ms
ESP32-S3 LX7 実機1.19 s
ESP32 Core2 LX6 実機約 2.8 s

16局が混み合う WSJT-X 参照録音での実測。差はほぼ純粋な CPU 性能比で、アルゴリズム上のオーバーヘッドはありません。 WSPR も 1214秒 → 101.6秒まで詰め、9/9 を維持したまま 120秒スロットに収まりました。

設計 — Protocol トレイト

1つのモードは 実行時に1バイトも占めない型として書かれ、その上に ModulationParams（トーン数・シンボルレート・Gray 写像・GFSK 整形）、 FrameLayout（シンボル数・スロット長・同期配置）、 Protocol（どの FEC と、どのメッセージ符号を使うか）を実装します。 共通パイプラインはすべて P: Protocol にジェネリックで、コンパイル時に各モードへ単相化されます — vtable なし、動的ディスパッチなし。抽象化のコストはコンパイル時間だけで、実行時にはゼロです。 実測で src/ の約3分の1（58.9k 行中 18.7k 行）が全モード共通のジェネリックコードです。

これが効くということ：FST4-60A の追加は、ZST 1つへの trait 実装 + レジストリ1行でした（共通コードには一切触れていません）。 Fortran では、モード間の「同じであり得たはずの部分」はソースファイル間のコピー＆ペーストとして現れます。ここではそれを型で表現しています。

一緒に作りませんか

  • ブラウザで動く FT8 — WASM PWA のフロントエンド（ライブラリ側は wasm32 で動きます）
  • Android / iOS アプリ — C ABI は用意済み、JNI の骨組みもあります
  • ESP32 以外のマイコン — RP2350、Cortex-M。FFT を1つ渡せば動くはずですが、まだ誰も試していません
  • CoreS3 の送信側 — 残るは BLE CI-V、ADIF ログ、送信キーイング
  • JT65 の残差 — 自前コーパスでは差ゼロ、実バイナリにはまだ届かず。原因未特定 — 面白い問題です
