# mfsk skimmer — ユーザマニュアル

SpyServer から FT8・FT4・WSPR などの WSJT-X のモードをデコードします。PC だけで動き、手元に無線機は要りません。

Windows と macOS のアプリ（バージョン 1.0）のマニュアルです。画面に何が出るか、各設定が何をするかを
説明します。なぜそう動くのかは [`apps/skimmer/README.md`](../../apps/skimmer/README.md) にあり、
コマンドライン版もそこにあります。

> **サンプルアプリです。** 受信専用で、サポートの約束はなく、`mfsk-core` を実際の入力源から
> 動かす例として書かれました。**PSK Reporter への報告機能は入っていて、既定はオフです。オンにすると
> 本物の PSK Reporter へ送ります**（10 章）。インストーラは発行元の証明書で署名されていないため、
> 初回には各 OS が警告を出します（3 章）。

---

## 1. 何ができるか

スキマーは [SpyServer](https://airspy.com/download/)（背後に Airspy HF+、Airspy、RTL-SDR のいずれか。LAN 内でも遠隔でも可）に
接続し、無線機の IQ ストリームを受け取って、与えたチャンネルをすべて、その1本のストリームからデコードします。
チャンネルとは、ダイヤル周波数（USB）上のモードのことで、たとえば `FT8  7 074.0 kHz` です。

| モード | スロット | 備考 |
|---|---|---|
| FT8 | 15 s | スロット開始から約 11.8 s で見つかった行を WSJT-X と同じように先に出し、残りは最後に出す |
| FT4 | 7.5 s | |
| FST4-15 / 30 / 60 / 120 / 300 | 15〜300 s | |
| WSPR | 2 min | |
| JT9, JT65 | 1 min | |
| Q65 (15A, 30A, 60A〜60E, 120D, 120E, 300A) | 15〜300 s | プリセットとモード一覧が出すサブモード |
| JTTY | なし | WSJT-X 3.2 のキーボード通信モード: メッセージは受信しながら伸びる |

単なるデコーダに加えて、次のことができます。

- **複数チャンネルの同時受信**（1本のストリームから）: 7 041 kHz の FT8、7 074 kHz の FT8、7 047.5 kHz の FT4 で、接続は1本です。
- **複数のサーバ**（最大4つ）と、1台のサーバでの**バンドの巡回（ローテーション）**。1台の SDR が全バンドを同時に聞けないときのためです。
- **SDR# とのラジオの共有**: スキマーは客（ゲスト）になり、あなたが聞いているラジオを動かしません。
- チャンネルごとの**ウォーターフォール**と、聞こえたもの全部の**データベース**（地図、統計、タイムラプス付き。
  9 章）。

受信専用で、送信はしません。

## 2. 必要なもの

- PC から届く **SpyServer**: `192.168.1.26:5555` のようなアドレス。LAN 内なら、SDR# が使うアドレスとポートです。
- **約1秒以内で正しい PC の時計**: どのモードもタイムスロットでデコードします（11 章）。
- Windows 10 または 11（x64）、または Apple silicon の macOS。Intel Mac と Linux のビルドはありません。それらでは
  コマンドライン版をビルドしてください。
- 自分のコールサインと、グリッドロケータ。聞こえた局の距離と方位、日の出・日の入り、そして（有効にしたとき）
  QSO のアプリオリデコードに使います。

## 3. インストール

最新の *mfsk skimmer* リリース
（[スキマーのリリース一覧](https://github.com/jl1nie/mfsk-core/releases?q=skimmer)）の *Assets* からインストーラをダウンロードします。

| プラットフォーム | ファイル |
|---|---|
| Windows 10/11 (x64) | `mfsk-skimmer-vX.Y.Z-windows-x64-setup.exe` |
| macOS (Apple silicon) | `mfsk-skimmer-vX.Y.Z-macos-arm64.dmg` |

どちらも発行元の証明書で署名されていないため、各 OS が初回に1度だけ警告を出します。

### Windows

セットアップを実行します。*Windows によって PC が保護されました* と出たら、*詳細情報*、続いて *実行* を選びます。
現在のユーザ用にインストールされ（管理者権限は不要）、`%LOCALAPPDATA%\mfsk skimmer` に入り、スタートメニューに *mfsk skimmer* が
追加されます。

設定とデータベースはインストール先にありません（12 章）。そのため、Windows のアプリ一覧からアンインストールしても
残り、新しいバージョンを上からインストールしても残ります。

### macOS

ディスクイメージを開き、アプリを *アプリケーション* へドラッグします。アプリは Developer ID ではなくアドホック署名なので、
公証されておらず、Gatekeeper が最初の起動を止めます。

- **macOS 14 以前:** アプリを右クリックして *開く* を選びます。
- **macOS 15 以降:** アプリを一度開き（拒否されます）、システム設定 → プライバシーとセキュリティ → 下へスクロールして
  *「mfsk skimmer」はブロックされました* → *このまま開く*。
- どちらの場合も、ターミナルから: `xattr -dr com.apple.quarantine "/Applications/mfsk skimmer.app"`。

最初の接続で求められたら、**ローカルネットワークへのアクセスを許可**してください。拒否してしまったときは、システム設定 →
プライバシーとセキュリティ → ローカルネットワークで有効にします。拒否されていると、アプリには
`No route to host (os error 65)` と出ます。

### 初回起動

1. **設定**（左上の ⚙）を開きます。*Server* タブで、サーバの **Address**（`host:5555`）、**My call**、**Grid**（自分のロケータ。
   SpyServer が遠隔にあるときはアンテナのロケータ）を入れます。
2. 設定を閉じ、**Channels** の下で *Presets* のバンドを選び、聞きたいモードをクリックします（`+ FT8 7074.0 kHz`）。
3. **Connect** を押します。

デコードは、次のスロットが終わると現れます。FT8 は15秒ごと、WSPR は2分ごとです。設定は保存され、次回の起動で
復元されます。

## 4. ウィンドウ

```
┌───────────────────────────────────────────────────────────────────────────────┐
│ ●Server 1  ●Server 2  +   ⚙  [Connect]   status: Decoding · delay · drift      │  header
├──────────────────────┬────────────────────────────────────────────────────────┤
│ Channels             │ [Waterfall] [Analysis]                                   │
│  Server 1            │  ┌thumb┐┌thumb┐┌thumb┐   one small waterfall per channel │
│   FT8 7074.0  ⚙ ✕   │  └─────┘└─────┘└─────┘                                   │
│   FT4 7047.5  ⚙ ✕   │  ┌─────────────────────┐ the chosen channel, large        │
│  ...                 │  │                     │                                  │
│  [FT8 ▾][dial kHz]   │  └─────────────────────┘                                  │
│  Presets [40m ▾]     │  Decodes: UTC  Mode  MHz  dB  DT  Message                 │
│   + FT8 7041.0 (JA)  │                                                          │
└──────────────────────┴────────────────────────────────────────────────────────┘
```

### ヘッダ

- **サーバのチップ。** サーバごとに1つで、ドット（●）と名前が付きます。ドットでそのサーバをオン・オフします
  （オフにすると接続を閉じますが、設定とチャンネルは残ります。オフのときドットは中抜きです）。名前をクリックすると、
  そのサーバのチャンネル、ゲイン、設定が表示されます。`+` でサーバを追加します（最大4つ）。
- **⚙** で設定を開きます（6 章）。
- **Connect / Disconnect** は、オンになっているすべてのサーバを開始・停止します。接続に関わる設定（アドレス、IQ 形式、
  チャンネライザ、時計、ウォーターフォール）は接続中は変えられません: *Disconnect to change these*。
- 選んだサーバの**状態**は、言葉、続いて数字で出ます。

| 状態（Phase） | 意味 |
|---|---|
| `Connecting to …` | TCP 接続を張っているところ |
| `Connected with control of the radio` / `Connected as a guest` | ラジオを同調させゲインを書ける / SDR#（または別のクライアント）が制御権を持っている（7 章） |
| `Decoding` | IQ が届いている。その下の行に IQ レート、中心周波数、チャンネライザが出る |
| `No channel fits the band around … MHz; waiting for the radio to move` | ラジオが、どのチャンネルも入らない周波数に同調している。ラジオが戻ればまたデコードする |
| `Disconnected (…); retrying` | 接続に失敗した。理由は括弧の中。再試行する |

  その後ろに小さな字で: 使用中の**時計**（PC clock または NTP）、その時計に対するストリームの**遅延（delay）**と**ずれ（drift）**、
  直近の周期で最も長かったデコード。強調表示されたものは、時計が合っていないか、ストリームに追いつけていないことを意味します
  （11 章）。PSK Reporter がオンなら、送信したスポット数もここに出ます。

### Channels（左）

サーバごとのチャンネルです。各チャンネルに、モードとダイヤル周波数、現在のスロットの間に満ちていく小さな円グラフ
（重ねるとスロットの境目までの時間が出ます）、**最後に聞こえたスロットでのデコード数**（今は聞こえていないときは灰色: ラジオの帯域外、
またはローテーションの順番待ち）、**⚙**（そのチャンネルのオプション。5 章）、**✕**（削除）が付きます。

接続中にチャンネルを追加・削除すると、**セッションが再起動します**（新しい組で切断して接続し直す）。そのため、受信中だった
スロットは失われます。チャンネルの*オプション*は再起動しません: 次のスロットから効きます。

### ウォーターフォール

ウォーターフォールがオン（設定 → *All servers*）のとき、*Waterfall* タブには、選んだサーバの全チャンネルの小さな
ウォーターフォールと、大きな1枚が出ます。小さいほうをクリックするとそのチャンネルが大きく出て、下のデコードも追従します。
両者の間のバーをドラッグすると高さが変わり、ダブルクリックで元に戻ります。*Fine*（設定）にすると、大きいほうが
2.9 Hz ではなく 1.5 Hz/ビンになります。デコードの位置はウォーターフォール上に印が付きます。

ウォーターフォールがオフのとき、タブの名前は *Decodes* になり、表だけが出ます。

### デコード表

どのモードも同じ行形式です。

| 列 | 意味 |
|---|---|
| UTC | スロットの開始 |
| Server | 聞いたサーバ（サーバが複数のときだけ出る） |
| Mode | チャンネルのモード |
| MHz | 信号の RF 周波数（ダイヤル + 音声周波数） |
| dB | 2 500 Hz 帯域での SNR（WSJT-X の報告と同じ） |
| DT | 信号のスロットからの時間ずれ（秒） |
| Message | 本文 |

**CQ** の行と、**自分のコール**を含む行は強調表示されます。行末の ✓ は、その行の `<...>` が、同じ周期の後のメッセージで
わかったコールサインで解決されたことを示します（行はその場で置き換わります）。*Detail* にすると **Sync**（同期スコア）と
**Err**（FEC が訂正した誤り数）が加わり、早出し（約 11.8 s）でデコードされた行に ⏱ が付きます。

表の上には、チャンネルの選択（*All channels* または1つ）、*Search call or text* の検索欄、*Clear* があります。Clear は
表を空にするだけで、**データベースにはすべてのデコードが残ります**（9 章）。

### JTTY

JTTY のチャンネルにはスロットがありません。メッセージは受信しながら伸びます。その一覧（同じやり方で選びます）は、メッセージ
ごとに1行で、メッセージが伸びる・完了する・見切られるたびに、**その行が置き換わります**。送信者と、あればそのロケータは、
データベースとステーション一覧に入ります。

## 5. チャンネル

### 追加

- **プリセット。** バンドを選ぶと、WSJT-X の既定の周波数リスト（全地域と Region 3 のエントリ）に、7 041 kHz の FT8（JA）と
  JTTY の周波数を加えたものが出ます。`+ …` をクリックして追加します。追加済みのものは灰色です。
- **手入力。** モードを選び、**ダイヤル**（USB のダイヤル周波数で、信号の周波数ではありません）を kHz で入れて、*Add* を押します。

チャンネルは、ヘッダで選んでいるサーバに追加されます。

### オプション（チャンネルの ⚙）

オプションは WSJT-X のデコーダのパラメータです。動作中のスキマーには**そのチャンネルの次のスロット**から、再接続なしで
効きます。空欄はそのモードの既定です。

| グループ | 項目 | 内容 |
|---|---|---|
| Search | Audio band (low–high) | 探索する音声周波数（`nfa`、`nfb`） |
| | Rx frequency, Tolerance | 単一信号モード（JT9、Q65、JTTY）が探す場所と、その周りの幅 |
| | Tx frequency | 送信周波数（`nftx`）。FT8 はその付近の相手局の仮説を試す |
| | Depth | `fast` / `normal` / `deep`（WSJT-X の `ndepth`。既定は deep） |
| A-priori | AP | off / CQ only / full。既定: FT8 と JT65 は off、他は full |
| | DX call | 1局を狙う: そのコールをデコーダに渡す（FT8、FT4、FST4、Q65） |
| | My call, grid | そのチャンネル固有の値（サーバのものと違うとき） |
| QSO in progress | His call, grid, progress | *My call* とあわせ、FT8、FT4、FST4 は WSJT-X の QSO 文脈のアプリオリデコードを導く |
| | Contest | NA VHF / WW Digi / ARRL Digi / Q65 pileup、EU VHF、Field Day、RTTY Roundup、Fox、Hound |
| Other | Average periods | JT65 と Q65: 同じ局を複数の周期で合算する |
| | Decode at 52 s | EME 遅延 |

オプションが設定されたチャンネルでは ⚙ が青くなります。重ねると要約が出ます。

## 6. 設定

⚙ で開きます。最初のタブは**選んだサーバ自身の設定**（そのサーバ名が付きます）で、最後のタブはすべてのサーバに共通です。

### Server

| 項目 | 内容 |
|---|---|
| Name | チップに出る名前。自分用、およびデータベース用 |
| Protocol | SpyServer（既定）、または rtl_tcp / rsp_tcp（下記） |
| Address | `host:5555`（rtl_tcp は `host:1234`） |
| rtl_tcp IQ | rtl_tcp のときだけ: Auto、8-bit、16-bit。どちらが来るかはサーバが決める。8 か 16 は確認のためで、もう一方を送るサーバは、起動のしかたを添えて断る |
| My call | このサーバでの自分のコールサイン。アプリオリデコードと PSK Reporter に使う |
| Grid | **このサーバのアンテナの**ロケータ。聞こえた局の方位・距離、日の出・日の入り、地図は、ここからの値になる。遠隔の SpyServer では、自分が座っている場所ではない |
| Sun today | そのロケータでの日の出と日の入り |
| Network delay (ms) | SDR からこの PC までの固定遅延。すべての到着時刻から差し引く。LAN ではゼロ。すべての局で DT が同じだけずれるときは、ここに入れる |
| IQ format | float32、または int16（バイト数が半分。遅い回線用）。SpyServer のみ |
| Channelizer | Auto、Direct、Filter bank。Auto は、チャンネルがある程度の数になるとフィルタバンクを使う |
| PSK Reporter | 10 章 |
| Give control back… | 7 章 |
| Gain | ラジオのゲイン指数。制御権があるときはスライダで書き込める（7 章） |

#### rtl_tcp と SDRplay の rsp_tcp

SpyServer が扱うのは Airspy と RTL-SDR です。扱わない機器、**SDRplay の RSP** には、SDRplay 自身の
[`rsp_tcp`](https://github.com/SDRplay/RSPTCPServer)（GPL-3.0。RSP をつないだ PC に SDRplay の API が要る）を使います。
これは `rtl_tcp` プロトコルを話し、素の `rtl_tcp` も同じように使えます。**Protocol: rtl_tcp / rsp_tcp** を選び、
`host:1234` を入れます。

- **8bit か 16bit か。** そのまま起動した `rsp_tcp` は 8bit の IQ を送ります（RSP の 14bit を 8bit に切る: ダイナミックレンジは小さい）。
  `rsp_tcp -E -b 16` は 16bit を送り、それを知らせてきます。スキマーはその知らせを読むので、*Auto* なら設定は要りません。
  ほかの選択は確認用です。
- **待ち受けアドレス。** `rsp_tcp` は `127.0.0.1` だけで待ちます。別の PC から使うには `-a 0.0.0.0` で起動します。信用できる
  ネットワークで。ポートに届く人は誰でも RSP を操作できます。
- **1本のストリーム、1つのバンド。** サーバは1つのレート（2.048 MS/s。コマンドライン版では `--rate`）で流し続け、止められません。
  スキマーは同調を変え、少し待ってから、ゲインを書き直します（同調の直後に書いたゲインは、RSP1 で反映されませんでした）。
  ローテーションは SpyServer と同じように使えますが、同調し直した直後の数秒は捨てます。*Gain* を設定しないと、サーバの
  自動ゲインのままで、ゲイン指数を入れると手動になります。
- **現状。** デコードは、代役の `rtl_tcp` サーバ（8bit と 16bit）に対してテストしています。実物の RSP1 では、接続、形式の通知、
  ストリームは動きましたが、その `rsp_tcp` が数分で `RSP failure` で止まり（読み取るだけでも）、実際の電波の FT8 は、
  まだこれでデコードできていません（#685）。

### Rotation

8 章。

### All servers

| 項目 | 内容 |
|---|---|
| Clock | **PC clock**、またはサーバ名つきの **NTP**。PC の時計は変えず、NTP サーバとの差をストリームの UTC に加える |
| Rotation follows the UTC clock | 8 章 |
| Decode threads | チャンネルあたり。前のスロットのデコード中に、次のスロットを別のスレッドでデコードする（既定は 4） |
| Early decode | FT8 の行を、スロットの約 11.8 s から出す（既定はオン） |
| Time budget | デコードがスロットの周期のうちこの割合まで走ったら打ち切って、そこまでの結果を出す。既定の 0 は、すべてのスロットを最後までデコードする |
| Waterfall, Fine | 4 章 |

## 7. SDR# とラジオを共有する

SpyServer はラジオの**制御権**を一度に1つのクライアントにだけ与え、**SDR# は接続したときにそれを取ります**（どちらが先でも）。
SDR# を閉じると、再接続なしで制御権が戻ります。

- **単独のとき**、スキマーが制御権を持ち、ラジオを自分の IQ の中心に同調させ、ゲインも書けます（設定 → Gain）。
- **SDR# の隣では**、スキマーは**ゲスト**です。ラジオを同調させず、ゲインも書きません（スライダは SDR# が設定した値を表示します）。
  置くのは自分の IQ の中心だけで、ゲストはそれをラジオの帯域内のどこにでも置けます。帯域の外に出るチャンネルは一時停止します
  （灰色、`0`）。SDR# はいつ起動しても閉じても構いません。
- **SDR# は *Stop* の後も接続を保持します**。サーバの枠と制御権も、SDR# を閉じるか入力源を切り替えるまで握ったままです。
  スキマーにゲインを書かせたいときは、SDR# を閉じてください。
- スキマーがゲストの間にバンドを変えるには、SDR# で同調し直します。スキマーは新しい中心で計画し直します。
- **Give control back…**（設定 → Server）は以前の動作です。制御権を与えられたら一度離れ、10秒後に再試行します。
  SDR# を入れるためにはもう不要で、既定はオフです。

サーバは、接続が閉じられたと分かるまで、そのクライアントを数え続けます。スキマーを接続したままスリープしたノート PC は、
枠を握り続けることがあります。**マシンをスリープさせる前に切断してください。** サーバが即座に接続を閉じたときは
`closed by the server (client limit?)` と出ます。

## 8. 複数のサーバと、バンドのローテーション

**複数のサーバ。** ヘッダの `+` でサーバを追加します（最大4つ）。それぞれが自分のアドレス、コール、ロケータ、形式、
チャンネライザ、ゲインを持ち、データベースにはどのサーバが何を聞いたかが記録されます。SpyServer 1台は SDR 1台で、
中心も IQ レートも1つなので、同時に聞くバンドを増やすには、サーバを増やすか、ローテーションを使います。

**ローテーション**（設定 → Rotation → *Rotate through the bands of its channels*）。サーバのチャンネルがあるバンドに、
順番に出番を与えます: `20m を10分、40m を10分、80m を10分、そしてまた最初から`。1つのバンドのモードは同時に聞こえます。

- 1ステップは最低 **4分**で、そのバンドのモードのスロットの整数倍に切り上げられます（WSPR のスロットは2分なので、5分は6分になります）。
  同調し直しには1〜2スロットかかります。ステップの最後のスロットは、離れる前にデコードされます。
- バンドの順序は ▲ ▼ で入れ替えます。*Rotation follows the UTC clock* は周期を UTC の 0 時から数えるので、再起動しても
  同じ時刻には同じステップになります。
- **時間帯。** バンドが参加する UTC の時刻をクリックして選びます（24個の点）: 7 MHz は終日、14 MHz は昼だけ、3.5 MHz は夜だけ、
  または任意の組み合わせ。*day* と *night* はサーバのロケータでの太陽に従い（日の出の1時間前から日の入りの1時間後まで、
  およびその逆）、グレーラインは両方に入ります。*Follow the calendar* にすると、バンドは今日の時刻ではなく、毎日の日の出と
  日の入りに従います。
- **画面上では**、チャンネルの横に `⟳ 20m 3:21`（バンドと残り時間）が出ます。クリックするとそのバンドに**固定**され
  （`⏸ 20m held`）、もう一度クリックすると先へ進みます。`‹` と `›` は直前・直後のバンドへ今すぐ移ります。移った先のバンドは、
  その時点から1回分の出番をまるごと得ます。
- **ウォーターフォールのサムネイル**は、いま聞いているバンドのものに**赤い枠**が付きます。ローテーション中に、どのバンドが現在のものかが一目で分かります。

## 9. 解析（Analysis）

すべてのデコードは、データベースのファイル（`skimmer.db`）に記録され、**Analysis** タブはそれを読みます。そのため、表に残っているものだけでなく、
聞こえたもの全部が対象になります。

**クエリバー**は、3つのビューに出すものを絞ります: **期間**（プリセット、または from–to）、**コール**・**グリッド**・**メッセージ本文**の
正規表現（`^JA` は JA で始まるコール、`^(JA|JH)\d`）、**CQ** の種類（any、every CQ、plain、DX、POTA、SOTA、TEST）、**バンド**と**モード**、
**SNR** の範囲、自分のグリッドからの**距離**、**方位**（コンパスの方向をクリック）、**サーバ**。*Search* で適用し、*Reset* で解除します。

- **Map。** 聞こえた局を、自分のロケータ（またはサーバ）を中心にした世界地図に出し、大圏コースの線を描きます。バンドを2つ以上選んでいると、
  線はバンドで色分けされます。*grey line* で昼と夜を示します。**Play** は期間を、1〜60分の窓で、毎秒 1〜16 窓の速さの
  タイムラプスとして再生します。
- **Results。** **局**の一覧（コール、グリッド、バンド、聞こえた回数、最良の SNR、距離、最初と最後に聞こえた時刻）と、開いた局について
  のデコード1件ずつ、およびその局が1日のうちどの時間帯にいるか。
- **Database。** ファイルの操作: *Open another…* は、スキマーの記録先を変えずに別のファイルを読みます。デコードを残すかどうか、
  `STATUS.log` のフォルダ、**Clear out old decodes**（古いデコードの削除）、**Compact the file**（ファイルの圧縮）、**Export**（クエリ、
  過去24時間、7日または30日、すべて）。

ファイルとフォルダは、切断中にここで選びます。Documents が OneDrive と同期されていると、データベースもそこで同期されます。
書き込み中のデータベースは同期フォルダに向かないので、望まないときは別のフォルダを選んでください。

## 10. PSK Reporter

スキマーは、デコードしたものを、WSJT-X が送るのと同じパケット（UDP 上の IPFIX）で、[PSK Reporter](https://pskreporter.info/) へスポットとして
送れます。**1.0.0 からは、送信先は PSK Reporter 本体です**。PSK Reporter の作者が、スキマーの本番送信に了承しました。
送信先の設定項目はありません。プログラムに固定されています。**既定はオフ**です。（0.9.x のベータは PSK Reporter の
テスト用リスナー（何も記録されません）へ送り、画面に *Test only* と出ていました。その表示はなくなりました。）

オンにすると（設定 → Server → *PSK Reporter*）、設定したコールとロケータの名義でスポットが PSK Reporter に載ります。
先にそれらを確認してください。ヘッダに送ったスポット数と直近のエラーが出て、重ねると内訳が見えます。

- **My call** と、4文字以上の **Grid** が必要で、それらの名義で報告されます。**ロケータはアンテナのもの**なので、遠隔の SpyServer では
  自分が座っている場所ではありません。サーバごとに別々の受信局として PSK Reporter に現れます（アンテナの場所1か所につきコール1つ）。
- *Antenna* は、受信局の記録に入る自由記述です。
- 何を報告するかは、WSJT-X のスポットの規則に従います（FT8、FT4、FST4、JT9、JT65、Q65、JTTY。**WSPR は対象外**）。データグラムは
  最大5分に1つ、満杯になったときだけそれより早く、コールサインはバンドごとに5分に1回です。切断したときに送信待ちだったスポットは
  送られません。

## 11. 時刻と、PC の時計が重要な理由

スロットを使うモードはすべてタイムスロットでデコードするので、スロットが UTC と合っている必要があります。PC の時計が約1秒を超えて
ずれていると、信号の頭が欠けたり、DT が全体にずれたりします。スキマーは IQ に UTC を付けます。

- PC の時計が正しく保たれていないなら、*Clock → NTP*（設定 → *All servers*）を使います。PC の時計自体は変更されません。
- 状態の行に、使用中の時計、ストリームの**遅延（delay）**、その時計に対する**ずれ（drift）**が出ます。**すべての**局の DT が
  同じだけずれるなら、ラジオから PC までの固定遅延がゼロではありません。サーバの設定の *Network delay* に入れてください。
- Connect は、応答しない NTP サーバを待ちません。PC の時計を使い、状態の行に `NTP … failed … using the PC clock` と出ます。
- 強調表示されたずれや、スロットより長い最長デコードは、PC が追いついていないことを意味します。チャンネル数、*Decode threads*、
  いちばん重いチャンネルの Depth を下げてください。

## 12. ファイルの場所

| 内容 | Windows | macOS |
|---|---|---|
| 設定 | `%APPDATA%\io.github.jl1nie.mfsk-skimmer\settings.json` | `~/Library/Application Support/io.github.jl1nie.mfsk-skimmer/` |
| データベース `skimmer.db`、健全性ログ `STATUS.log` | `Documents\mfsk-skimmer\` | `~/Documents/mfsk-skimmer/` |

どちらも Analysis → Database で変更できます。`STATUS.log` は、長時間運用のための健全性イベントの記録で、1イベントにつき1行です。
5 MB を超えると `STATUS.log.1`（古い世代を1つ）になり、同じ失敗を繰り返すサーバは、1行と回数で済みます。GUI は
`ALL.TXT` を書きません。コマンドライン版は書きます（`--log`）。

## 13. トラブルシューティング

| 症状 | 意味 |
|---|---|
| macOS で `No route to host (os error 65)` | ローカルネットワークへのアクセスが拒否された: システム設定 → プライバシーとセキュリティ → ローカルネットワーク |
| `closed by the server (client limit?)` | サーバのクライアント枠が埋まっている（SDR# が開いている、または接続したままスリープしたスキマー）。どれか1つを閉じる |
| つながらない | アドレスとポートは SDR# が使うものと同じでなければならない。まず同じ PC の SDR# で試す |
| `No channel fits the band around … MHz` | ラジオが（SDR# によって）、どのチャンネルも入らない周波数に同調されている。同調し直すか、そのバンドのチャンネルを追加する |
| 接続できているのにデコードが出ない | 時計（11 章）。ダイヤルが信号の周波数になっていない。バンドが閉じている。ゲインが低すぎる |
| すべての局で DT が同じ | *Network delay* を入れる（6 章） |
| チャンネルが灰色で `0` | ラジオの帯域外、またはローテーションの順番待ち |
| macOS がアプリをブロックする | 3 章 |
| Windows が *PC が保護されました* と警告する | 3 章 |

## 14. 制限

- Windows 10/11 x64 と、Apple silicon の macOS のみ。インストーラは署名なし。
- サンプルアプリです。報告や質問は GitHub の Issue で歓迎しますが、サポートの約束はありません。
- macOS 版は CI で作られており、すべての Mac で動かしたわけではありません。
- PSK Reporter への報告は本物のサービスへ、設定したコールとロケータの名義で送られます（10 章）。
- コマンドライン版（`skimmer`）には、デコーダのすべてのオプションがあり、`ALL.TXT` 形式のログを書きます。
  [`apps/skimmer/README.md`](../../apps/skimmer/README.md) を参照してください。
