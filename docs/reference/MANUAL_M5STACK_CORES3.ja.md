# M5Stack CoreS3 受信機 — ユーザマニュアル

1つのバイナリに4つの受信機、そして USB ポートに無線機。

このボードは本プロジェクトの主力ハードウェアです。M5StickS3 と違って
USB ホストになれるため、マイクを経由せず**トランシーバの USB Audio
から直接音声を取ります**。2026-08-23 に IC-705 の 40 m 受信で検証し、
1スロットあたり FT8 を 6〜8 局、−24 dB までデコードしています。

StickS3（デモ／音響経路のボード）は
[`MANUAL_M5STICKS3.ja.md`](MANUAL_M5STICKS3.ja.md) を参照してください。
ボード非依存のデコーダ側の話は [`EMBEDDED.ja.md`](EMBEDDED.ja.md) です。

---

## 1. 何ができるか

4つの受信機が1つのイメージを共有します。どれが動くかは NVS に保存され、
**タッチパネルから切り替えます**。モード変更に再書き込みが不要なのが
重要で、USB ホストドライバを入れると書き込みに使うポートが無くなるため
です。

| モード | 内容 | 無線機 |
|---|---|---|
| `uac` | 無線機の USB Audio から FT8 | 要 |
| `wspr` | WSPR 受信機（スポット一覧、wsprnet 送信） | 要 |
| `fst4` | FST4 広帯域モニタ | 要 |
| `decode` | イメージに焼き込んだ WAV から FT8 | 不要 |

`decode` はデモ用で、無線機もアンテナも不要です。**ボードが正常かを
確かめる最速の手段**でもあります。

## 2. ハードウェア

### 必要なもの

- **M5Stack CoreS3**（ESP32-S3、16 MB flash、8 MB PSRAM）。CoreS3 SE も可
- 書き込み用の **USB-C ケーブル**（PC へ）
- `decode` 以外: **USB Audio** を持つトランシーバと USB-C ケーブル

### 電源の制約 — ここは理解が必須です

**USB-C コネクタ1本で給電を受けながら給電を出すことはできません。**
そのためファームは**起動時に1回だけ**、VBUS の有無から役割を決めます。

- **VBUS あり**（PC 接続）→ **ペリフェラル**のまま。充電され、シリアル
  コンソールが生き、書き込みできます。**この状態では無線機と通信しません**
- **VBUS なし**（バッテリ駆動）→ **ホスト**になり、コネクタへ給電して
  無線機を列挙します

したがって実運用の手順は「**PC から抜く → ボタンを短く押してリセット →
無線機を挿す**」です。抜くだけでは切り替わりません（判定は起動時に
済んでいます）。

ホストモードでは USB-Serial-JTAG が消えるので、**書き込みもシリアル
コンソールもできません**。唯一の経路は WiFi です（§6）。

### このファームが使う内蔵デバイス

| デバイス | アドレス | 用途 |
|---|---|---|
| AXP2101 | 0x34 | 電源レール、電池／VBUS 電圧 |
| AW9523B | 0x58 | LCD バックライト、タッチ電源、USB ホスト VBUS |
| FT5x06 | 0x38 | タッチパネル |
| BM8563 | 0x51 | リアルタイムクロック（§7） |

## 3. 初回セットアップ

### 3.1. ツールチェーン

```sh
cargo install espup espflash
espup install
source ~/export-esp.sh    # ビルドする全シェルで必要
```

### 3.2. 設定

```sh
cd embedded-poc/m5stack-cores3-app
cp cfg-sample.toml cfg.toml
$EDITOR cfg.toml          # §4 参照
```

`cfg.toml` は gitignore 済みです。**一度もコミットされていませんし、
してはいけません** — WiFi のパスフレーズが入ります。

### 3.3. ビルドと書き込み

```sh
source ~/export-esp.sh
cargo build --release
../scripts/flash-monitor.sh \
    target/xtensa-esp32s3-espidf/release/mfsk-core-m5stack-cores3-app \
    logs/boot_$(date +%F).log 110
```

`espflash` を直接使わずスクリプトを使ってください。フラッシュサイズを
自動検出し（誤った値を書くと `erase-flash` でも直らない状態になります）、
**失敗した書き込みを成功と区別**します。

| exit | 意味 |
|---|---|
| 2 | シリアルポートが使えない |
| 3 | 書き込みが完了しなかった（キャプチャ窓が短すぎる） |
| 4 | 書き込みは成功したが DOWNLOAD モードに留まった |

exit 4 はボタンの**短押し**で復帰します。長押し（約2秒）は逆に DOWNLOAD
モードに**入る**操作です。

`Segment … has not changed, skipping write` は**成功ではありません** —
チップは前のバイナリを実行し続けます。ソースを触って実書き込みを
強制してください。

## 4. `cfg.toml` リファレンス

`build.rs` がコンパイル時に読むので、変更にはリビルドが要ります。

### `[wifi]`

```toml
ssid = "your-ssid"
psk  = "your-passphrase"
pc_ip = "auto"      # または "192.168.1.9" / "255.255.255.255"
port = 9999
```

**このボードで WiFi はデバッグ用の贅沢ではありません。** 次を担います。

- **NTP** — FT8 のスロットグリッドがこれ無しではデコードできません（§7）
- **HTTP 設定ページ**（WSPR のコールサイン、バンド、wsprnet）
- **UDP ログ** — ホストモードでは唯一のコンソール

セクションを省くか `ssid = ""` で WiFi を無効化できます。起動はします。

`pc_ip = "auto"` は DHCP のリースから**ディレクテッドブロードキャスト**を
計算します。アクセスポイントは省電力の都合で `255.255.255.255` を落とす
ことが多い一方、ディレクテッドブロードキャストは通すので、こちらを推奨します。

### `[station]`

```toml
call = "JA1ABC"
grid = "PM95"
```

FT8 の QSO ステートマシンがメッセージを組み立てるのに使います。
**受信専用局なら両方空にしてください** — FSM は停止したままになり、
それが正しい状態です。**他人のコールサインで名乗るより望ましい**です。

WSPR はここではなく HTTP 設定ページからコールサインを取ります。リビルド
より頻繁に変えるものだからです。

### `[app]`

```toml
boot_mode = "uac"
```

**上書きではなく seed** です。NVS にモードが無いときだけ書かれます。
タッチピッカーが実行時に NVS を書くので、毎回再適用される値だと次の
起動でその選択が取り消されてしまいます。

値: `uac` | `wspr` | `fst4` | `decode`。省略すると NVS の値が使われます。

### ビルド時スイッチ

コンパイル時に読まれる環境変数です。すべて既定オフ。

| 変数 | 効果 |
|---|---|
| `MFSK_CORES3_FORCE_UAC=1` | 外部給電下でも USB ホストになる。PC へ逆給電するのでベンチ用のみ |
| `MFSK_CORES3_USB_PANEL=1` | 10行の USB 診断パネルを描く（デコード行を消費） |
| `MFSK_WSPR_SYNTH=1` | 無線機が無いとき WSPR のスロット音声を合成する |
| `MFSK_FST4_REPLAY=1` | 無線機が無いとき FST4 の焼き込みスロットを再生する |

後ろ2つは**無線機なしの机上作業のため**にあります。**既定でオフなのは、
生成物が実デコードと区別できないから**です。合成した `K1ABC` が2分ごとに
スポット一覧へ載り、再生スロットは同じ局を延々と表示します。**聞こえて
いない受信機は、聞こえていないと言うべき**です。

読み込む資産は Cargo feature (`wspr-golden` / `fst4-replay`) の後ろに
あるので、オフならバイトごと含まれません — イメージで 1.8 MB、書き込み
のたびに効きます。

## 5. モードの切り替え

画面のどこでも**約 0.8 秒**押し続けるとオーバーレイが出ます。4つの
受信機が並び、現在のモードに `*` が付きます。

1. **モードをタップ** — その行が緑になります。名前は残ります（確認の
   ためのステップなので、確認対象を消しては意味がありません）
2. **下のバーを押す** — `SWITCH TO <モード>` と書かれています。押下中は
   オレンジ、確定すると緑地に `SWITCHING TO <モード>`
3. NVS に書き込んで再起動します

オーバーレイの外をタップすると閉じます。**端に 14 px の余裕**があるので、
少し外した押下は解除ではなく確定になります。

パネルを使わずに変えるには、NVS を消して `cfg.toml` の `boot_mode` を
設定します。

## 6. コンソールの無いボードを読む

ホストモードでは USB シリアルデバイスが存在しません。以下はその前提です。

### UDP ログ

```sh
embedded-poc/scripts/udp-log-listen.sh 9999 logs/session_$(date +%F).log
```

**ボードが起動する前に**開始してください。WiFi の接続は電源と USB の
判定より数秒遅いので、それらの行はステージングリングに入り、sink が
できる頃には上書きされています。

### `[boot-summary]`

まさにその理由で、各受信機は sink ができた時点で起動時の重要事実を
**一度だけ再送**します。

```text
[boot-summary] mode=UAC host_mode=true start_host: host+class driver installed OK
[boot-summary] rtc: clock from BM8563 2026-08-23 13:27:05Z
[boot-summary] AXP 0x90=0x8b status1=0x18 | AW9523 OUT0=0x33 OUT1=0x83 | bat=3889mV vbus=16373mV
[boot-summary] i2c: 34 38 40 51 58 69
```

読む順序:

- `host_mode` — ファームの判定。無線機を挿しているのに `false` なら、
  起動時に VBUS があったということ。抜いてリセットしてやり直す
- `start_host` — USB ホストドライバが実際に入ったか
- `rtc` — 時計がチップから来たか、NTP 待ちか
- `OUT1` の bit7 と `OUT0` の bit1/bit5 — VBUS の3つのイネーブル。
  **3つとも High でないと列挙しません**
- `i2c` — ライブスキャン。出力レジスタの読み戻しは「書いた値」を返す
  だけですが、これは**今応答しているデバイス**を示します

### リンクバー

全モード共通、画面下端 14 px です。

```text
USB H STREAM d1 V111 v---- b3.89 W-36
      │      │  │    │     │     └ WiFi RSSI、未接続なら `down`
      │      │  │    │     └ 電池電圧
      │      │  │    └ VBUS 電圧、ADC が読めないときは `----`
      │      │  └ BOOST_EN / USB_OTG_EN / BUS_OUT_EN
      │      └ 開いている USB デバイス数
      └ CHARGE | NODEV | STREAM(緑) | NOHOST(橙) | ERROR(橙)
```

`H`/`P` は**ファームが選んだ役割**で、ドライバが立ち上がったかどうかでは
ありません。したがって `H NOHOST` は異常であり、そう読めます。`V!!!` は
I/O エキスパンダが応答しなくなった状態です。

ホストモードでは AXP2101 の VBUS ADC が**自分の昇圧出力を見られず**
フルスケールに張り付くので `v----` と出ます。これは正常で、その状況では
電池電圧のほうが意味を持ちます。

## 7. 時刻 — デコードがこれに依存する理由

全受信機がスロットグリッドを UTC に合わせます。FT8 の許容は 15 秒
グリッドに対して ±2.5 秒なので、**時計の無いボードは何もデコードしません**。
波形は信号で埋まり、候補も見つかり、そのどれ一つ復調できません。
**このハードウェアで最も紛らわしい失敗モード**で、デコーダの故障と
見分けがつきません。

供給元は2つ、この順です。

1. **BM8563 RTC** — WiFi より前、`pmic::init` で読みます。電池
   バックアップなので**電源断を跨ぎ、WiFi 圏外でも効きます**
2. **NTP** — それを精密化し、結果を RTC に書き戻します

どちらから来たかは `[boot-summary]` が示します。画面では、ステータス行に
UTC が出て、リンクバーに時計があれば `T`、無ければ `-` が出ます。

新品のボードやバックアップ電池が切れたボードは `BM8563 VL` を報告して
NTP を待ちます。一度同期すれば、以降の起動は最初から時計を持ちます。

## 8. スロット単位のログ

各モードが1スロット1行で、音源・結果・時間予算を出します。

**FT8**

```text
SLOT[7] src=uac p1=30 ready=30 defer=0 dec=7 tail_win=… slot_wait=981068us
```

`src=uac` か `src=wav` かで、実音声か焼き込み録音かが分かります。`dec` が
デコード数です。`slot_wait` がゼロ近傍なら、次のスロットが来た時点でまだ
処理中だったということで、別に `OVER BUDGET` の警告が出ます。

混雑したバンドではこの警告は**異常ではなく想定内**です。15 秒は本質的に
窮屈で、フロントエンドのコストは信号量に比例し、局は交互周期で送信する
ので、混んでいる側は時間切れになって候補を後回しにします。

**WSPR と FST4 は逆**です。モニタのループは**意図的に大きな余裕**を
持たせた設計で（WSPR は 2 分スロットに対して処理は数秒）、その余裕が
混雑スロット・WiFi のバースト・表示タスクを吸収して候補を落とさないように
しています。**低い占有率は設計が効いている証拠**で削る対象ではなく、
**スロットを超えたら故障**です。

```text
wspr_app: slot 2316 src=uac decoded 3 station(s)
wspr_app::ddc: compute occupancy 8210 ms / 120000 ms slot budget (6.8%)
fst4_app::scan: slot 4 budget — 13643 ms of 60000 ms (23%), 46357 ms spare
```

## 9. トラブルシューティング

**何も列挙しない / リンクバーが `d0`**
`[boot-summary]` の `host_mode` を見てください。`false` なら起動時に
VBUS がありました。PC から抜いて短押しリセットし、無線機を挿します。

**波形に信号が見えるのに毎スロット `dec=0`**
原因は3つ、確認すべき順に:

1. **無線機が LSB になっている。** FT8・FST4・WSPR は**どのバンドでも
   常に USB** です。音声が LSB のバンドでも変わりません。LSB では
   トーン順が反転して同期パターンが原理的に一致せず、**波形は完璧に
   見えたまま何もデコードしません**
2. **時計が無い。** リンクバーが `T` ではなく `-`。§7 参照
3. **周波数違い。** 40 m の FT8 は 7074 kHz、WSPR は 7038.6 kHz です

**PC からボードが消えた**
ホストモードです。アプリが USB PHY を持っているので何も応答しません。
挿したまま短押しリセットすればペリフェラルとして戻ります。

**音声レベル** — `uac: rx tick` の `rms` は −40〜−25 dBFS 程度が適正です。
大きく下回るなら無線機の USB AF 出力レベルを上げてください。`clipped` が
0 でなければ高すぎます。

**WSL の場合**、チップのリセットごとに USB デバイスが再列挙されて Linux
から外れます。`embedded-poc/scripts/wsl-attach-board.sh` で再接続します。
