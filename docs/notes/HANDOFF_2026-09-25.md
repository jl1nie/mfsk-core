### What was learned, in five lines
1. The busy-band precision gap against `jt9` was not `/R` and not (mostly) the
   pass structure: it was the OSD. `osd174_91` picks the closest of all candidate
   codewords and checks the CRC once, on the winner; this crate checked every
   candidate. Wrong codewords from noise: upstream 5.8e-5, this crate 2.3e-3,
   after #455 9.0e-5 (iid Gaussian LLRs). Found by feeding both decoders the same
   input; candidate counts, nsync gates and the SNR gate had all been ruled out first.
2. `sync_min` 1.3 (what `jt9 -d3` runs) instead of 0.8 cut `.sic_early()` unexpected
   decodes 22 → 6 on the busy corpus at the same recall.
3. `mlag` 13 costs one signal on the fixed-point ship shape at `max_cand` 15-30
   (floor of `ft8_qso3_apoff_recall` is now 11); adopted on the maintainer's decision.
4. The cost of the OSD fix: busy recall -0.1 to -1.0 point; FT8 `itu_ld` (25-55 %
   plateau) crossing -5 → 0 dB; FST4 fading crossings 0.2 dB worse on average. The
   benefit: unexpected decodes to 0 on every sweep, ITU channel and noise file.
5. Full numbers and the commit-by-commit trail: `CHANGELOG.md` (top entries),
   `FT8_BENCHMARK.md` §13-§14, PR bodies #451 and #455.

### 2.1 FST4: is #457 a win or a trade? (before merging it)
It removed every unexpected decode (about 99 → 0) and cost 0.2 dB on the fading
crossings (four groups at ≥ 0.5 dB). What is missing is the reference: there are no
`jt9` FST4 crossings on this corpus, so nobody knows whether the new numbers are
nearer to WSJT-X or not.

  **I do not know the FST4 mode flag** (`jt9 --help`); `scripts/score-jt9-sweep.py`
  handles `ft8` and `ft4` only, and FST4 needs its own message / frequency criteria
  (see `tests/fst4_sweep.rs`) and the sub-mode in the file name. Extending the scorer
  is part of the job.
- Compare `fst4/<sub>/<channel>` crossings: this crate before #457 (in
  `sweep-baseline.json` at `1cfa029`), after (#457), and `jt9`.
- If the after-numbers are closer to `jt9` (or not further), merge. If they are
  further and the maintainer prefers sensitivity, the revert is one function
  (`osd_decode_npre_generic`, see the diff of #457).

### 2.2 #456: the rest of the generic OSD
`osd_decode_generic` (used by `osd_decode_deep`, so FT8's **AP path**, and by MSK144
and uvpacket) still verifies per candidate. Per mode: read the upstream OSD, compare
CRC-valid rates on identical LLRs, move the CRC to the winner where they differ by an
order of magnitude, then measure tier C before and after.
- Upstream false-rate programs: `scripts/osd-false-rate/build.sh <wsjtx>/lib 174|240 <draws>`.
  `decode174_91` costs ~2.5 ms a draw; `decode240_101` at `norder=3` **took over 30 s
  a draw**, which is why FST4 was never measured upstream at the depth it uses. Size
  the run so the expected hit count is a handful (5.8e-5 needs ~50 000 draws for 3
  hits); more is wasted.
- This crate's side: `tests/ft8_osd_false_accept.rs` (a gate) and
  `tests/fst4_osd_false_accept.rs` (`#[ignore]`, prints). Copy the pattern for MSK144.
- The AP path is guarded by its locked-callsign check, so it is the lowest risk of
  the three; measure it with an `apmask` (`osd174_91` takes one).

## 3. Decisions that were the maintainer's, so nobody reopens them by accident
- Faithful port: every upstream FT8/FT4 change is ported; a deviation needs a measured
  reason in a comment or the CHANGELOG. "No effect on the local corpus" is not a reason
  to skip. Compare same-change deltas (`jt9` old→new against this crate before→after),
  not absolute numbers.
- Tier C measures precision (unexpected decodes) as well as recall, and the baseline
  carries both.
- `mlag` 13 adopted; the ship floor is 11.
- The OSD follows the reference even at a sensitivity cost (#455). #457 is the same
  decision for FST4 and is left open for §2.1.

```sh

      -DWSJT_SKIP_QMAP=ON ../wsjtx-3.2-src && ninja jt9 ft8sim
```
Running `jt9` over a corpus: one file per process in a fresh temp dir,
`jt9 -8 -d <1|2|3> -a . -t . file.wav` (FT4 is `-5`). Its output has ` ?` and ` aN`
markers after the message and `~` (FT8) / `+` (FT4) as the mode character; a scorer that
does not strip them counts correct AP decodes as misses.
`scripts/score-jt9-sweep.py` (sweeps) and `scripts/score-jt9-busy.py` (busy corpus,
reads `truth.csv`) do it right; both print how the layout has to look.

**Instrumented `jt9` (candidate counts), if needed again.** Two lines in a copy of the tree:
in `lib/ft8/ft8b.f90` right after the `if(nsync.le.syncmin) then ... endif` block,
`write(6,'(a,i3,f8.1,f7.2)') 'DBG NSYNCPASS',nsync,f1,xdt`; in `lib/ft8_decode.f90` right
after the `call sync8(...)` line, `write(6,'(a,i5,i3,i4)') 'DBG NCAND',ncand,ipass,nzhsym`.
On five noise files at `-d3` this gave 141-193 candidates and ≈ 27 nsync-passing per pass,
four passes (pass 3 is skipped without decodes) — comparable to this crate's counts, which
is how "exposure" was ruled out in #452.

## 5. Regenerating the corpora (`embedded-poc/assets/*_sweep/`, gitignored)

Everything is deterministic: `scripts/sim_sgran_stub.c` replaces upstream's `sgran()` and
seeds from `MFSK_SIM_SEED` (default 1), and the build scripts link it. A corpus is a function
of (simulator binary, arguments, seed); the baseline travels with it. Details and the
reasoning: `BENCHMARKS.md`, "Generating the tier-C corpora".

```sh
# existing corpora: simulators from the 2b9d654 tree
scripts/build_ft8sim.sh  ../wsjtx-2b9d654 target/ft8sim-2b9
scripts/build_ft4sim.sh  ../wsjtx-2b9d654 target/ft4sim-2b9
scripts/build_fst4sim.sh ../wsjtx-2b9d654 target/fst4sim-2b9
scripts/gen_ft8_sweep_wavs.sh  target/ft8sim-2b9/ft8sim   embedded-poc/assets/ft8_sweep
scripts/gen_ft4_sweep_wavs.sh  target/ft4sim-2b9/ft4sim   embedded-poc/assets/ft4_sweep
scripts/gen_fst4_sweep_wavs.sh target/fst4sim-2b9/fst4sim embedded-poc/assets/fst4_sweep

# new corpora: ft8sim from v3.2.0-rc1
scripts/build_ft8sim.sh ../wsjtx-3.2 target/ft8sim-3.2
FT8_CHANNEL_SET=itu scripts/gen_ft8_sweep_wavs.sh target/ft8sim-3.2/ft8sim embedded-poc/assets/ft8_itu_sweep
```

## 6. Running tier C

```sh
export MFSK_FT8_SWEEP_DIR=…/ft8_sweep MFSK_FT8_ITU_SWEEP_DIR=…/ft8_itu_sweep \
       MFSK_FT8_BUSY_DIR=…/ft8_busy_sweep MFSK_FT4_SWEEP_DIR=…/ft4_sweep MFSK_FST4_SWEEP_DIR=…/fst4_sweep
scripts/run-sensitivity-sweeps.sh ft8 ft8_itu ft8_busy      # groups: ft8 ft8_itu ft8_busy ft4 fst4 …
python3 scripts/sweep-regression-check.py target/sweep-csv/*.csv    # what the runner ends with
python3 scripts/sweep-regression-check.py --update-baseline target/sweep-csv/<the csvs of the groups you ran>
```
(A worktree does not contain the corpora; point the variables at the main checkout's assets.)
`ft8` also writes `ft8_sic_early.csv` (the `.sic_early()` strategy). The runner clears
`target/sweep-csv` each time, so refresh a baseline from one run that covers what you refresh.
FT8 groups take minutes (`ft8_itu`, 3060 files, the longest of them); **FST4 takes tens of minutes
and its groups run one after another**, not in parallel across groups. Tell the runner's output
to a log and read its per-group progress lines rather than waiting blind.

The busy test's defaults: `sync_min` 1.3 (`MFSK_FT8_BUSY_SYNC_MIN`), `max_cand` 600
(`MFSK_FT8_BUSY_MAX_CAND`), optional `MFSK_FT8_BUSY_SIC_ROUNDS=n` adds a `.sic_rounds(n)`
strategy that is not in the baseline.

## 7. Pitfalls that cost time

- `pkill -f <pattern>` matches your own shell when the pattern is in its command line.
- `sed -i` with a line number after an earlier edit shifts: print the line before and after.
- A long job with no progress output is indistinguishable from a hung one. Print progress from
  the start (the Fortran drivers here do); size statistical runs for a handful of expected hits.
- The runner's CSV directory is wiped per run; a CSV from an older run shows stale results.
- `--update-baseline` stamps the commit it was run at; run it from a clean, committed tree or
  the stamp says `-dirty`. A squash-merge leaves stamps pointing at commits that are only on
  the PR (GitHub keeps them); that is cosmetic.
- Compare against the baseline of the same corpus only. A single draw is worth up to 1.1 dB on a
  fading channel; a fixed seed buys reproducibility, not accuracy.
- Scoring `jt9` output: strip ` ?` / ` aN`; FT4 uses `+`, FT8 `~`.
- `cargo test -- --ignored` without `--test <binary>` runs every tier-C sweep in the crate; never.
