# Kotlin JNI scaffold for mfsk-ffi

A minimal end-to-end example: Kotlin class → JNI C shim → libmfsk.so.
Works on Android (NDK) and desktop JVM unchanged.

## Files

| File                        | Purpose                                                   |
|-----------------------------|-----------------------------------------------------------|
| `kotlin/Mfsk.kt`            | Kotlin wrapper with `open / decode / close` API           |
| `native/mfsk_jni.c`         | JNI shim marshalling ShortArray / Message<-> C ABI        |

The wrapper is ~90 lines of Kotlin and the shim is ~115 lines of C.
No JNA, no autogenerated bindings — explicit and easy to audit.

## Build (desktop JVM, Linux x86_64)

Useful for unit tests and headless integration. Requires a JDK with
`JAVA_HOME` set.

```bash
# 1. Build libmfsk.so (Rust side)
cargo build -p mfsk-ffi --release

# 2. Compile the JNI shim against the Rust library
cd mfsk-ffi/examples/kotlin_jni
gcc -shared -fPIC -o libmfsk_jni.so native/mfsk_jni.c \
    -I"$JAVA_HOME/include" -I"$JAVA_HOME/include/linux" \
    -I../../include \
    -L../../../target/release -lmfsk \
    -Wl,-rpath,'$ORIGIN:'"$PWD/../../../target/release"

# 3. Compile + run the Kotlin snippet (kotlinc must be on PATH)
kotlinc kotlin/Mfsk.kt -include-runtime -d mfsk.jar
java -Djava.library.path="$PWD:$PWD/../../../target/release" -cp mfsk.jar \
     -e 'println(io.github.mfskcore.Mfsk.version)'
```

## Build (Android, arm64)

For an Android app, add `libmfsk.so` and `libmfsk_jni.so` under
`src/main/jniLibs/arm64-v8a/` and consume `Mfsk.kt` from Kotlin code.

```bash
# Set the NDK version-qualified compiler
export NDK_CLANG=$ANDROID_NDK_HOME/toolchains/llvm/prebuilt/linux-x86_64/bin/aarch64-linux-android30-clang

# 1. Build libmfsk.so for arm64 (Rust side)
rustup target add aarch64-linux-android
CC_aarch64_linux_android=$NDK_CLANG \
CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER=$NDK_CLANG \
    cargo build -p mfsk-ffi --release --target aarch64-linux-android

# 2. Compile the JNI shim for the same ABI
$NDK_CLANG -shared -fPIC -o libmfsk_jni.so \
    native/mfsk_jni.c \
    -I../../include \
    -L../../../target/aarch64-linux-android/release -lmfsk
```

Then in your Gradle module:

```kotlin
// app/build.gradle.kts
android {
    ndkVersion = "27.0.11902837"
    defaultConfig {
        ndk { abiFilters += "arm64-v8a" }
    }
    sourceSets["main"].jniLibs.srcDirs("src/main/jniLibs")
}
```

Neither `libmfsk.so` nor the JNI shim (`libmfsk_jni.so`) is prebuilt
for Android — both are built locally as shown above (the shim is
~115 lines of C compiled against your own NDK toolchain).

## Memory model

- `Mfsk.open(...)` allocates a native handle; `close()` (or `use { }`)
  releases it.
- `decode()` internally allocates, populates, and frees a
  `MfskMessageList` on every call — Kotlin side sees only `List<Message>`.
- No Kotlin-visible pointer / handle besides the opaque `Long` stashed
  inside the `Mfsk` instance; attempting `decode()` after `close()`
  throws `IllegalStateException`.

## Design notes

- The shim returns `Array<String>` with a `|`-separated payload rather
  than a JNI struct-per-message. Simpler to keep in sync with Rust
  changes (only one JNI signature to maintain). For very hot paths
  consider a per-field `DirectByteBuffer` layout.
- Default protocol is `Protocol.FT8`; switch to `Protocol.FT4` (or any
  other `Mfsk.Protocol` value — all seven WSJT-family modes this
  library supports are enumerated) for other slot lengths.
- Thread safety: one `Mfsk` instance is **not** `Sync`. Each worker
  thread should `open()` its own handle. `lastError()` uses
  thread-local storage on the Rust side so concurrent decoders do not
  interfere.
